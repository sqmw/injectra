# 通用注入核心与 pre-runtime dev 模式

2026-11-12用户澄清后的当前方向，依据[D-012](../DECISIONS.md#d-012)，归属[T-040@v3](../TODO.md#t-040)。本页是范围真相；本轮按批准计划实施CLI收敛；通用dev能力尚未完成整体验收。

## 目标流程

**一次准备小型dev入口 → 现有编辑器修改外置增量 → dev通道更新目标 → 在真实App窗口查看效果。**

- 普通页面JS/HTML/CSS增量更新不反复修改、打包或签名应用资源。
- 初始化相关修改允许必要的页面重载或开发实例重启；不承诺所有JS无重启热替换。
- “查看”指目标App的真实效果与必要执行反馈，不另建模拟页面或编辑工作台。
- 首次入口准备可能涉及派生副本资源与签名；“在原App看效果”不等于本轮授权覆盖原安装包。
- 保留增量文件、版本/内容摘要、目标与执行回执，不要求先建设完整工作区、文件管理或持久化平台。

## 通用化与责任

接入按协议、宿主API、资源/完整性格式、平台复用。应用路径、入口位置和目标筛选是配置；不能把专用实现藏进配置后宣称通用。主题、DOM选择器和业务修改归载荷/插件，不进入注入核心。

CDP连接已开放的目标；Gadget仍需宿主页面桥；pre-runtime入口准备后通过运行期通道加载增量。它们共享Web执行契约与单一runtime，不把进程内JS执行等同于正确页面执行。

| 部分 | 承担内容 |
| --- | --- |
| 通用准备器/宿主适配 | 识别可用入口、准备引导、明确支持条件和准备结果 |
| dev loader/更新通道 | 读取或接收增量，在明确目标和上下文中执行，返回版本与结果 |
| 现有编辑器/真实App | 用户编辑代码，App自身显示效果，必要时重载或重启 |
| 增量作者/插件库 | 配色、选择器、业务行为及需要的清理逻辑 |

来源分为原App代码、Injectra引导、用户增量，无需混入一个可编辑目录；来源信息不等于能自动归因任意脚本副作用。core/Web/native分域、目标世代、Unknown不重放、既有清理接口及32方案阈值继续有效，未来内存操作不包装成页面JS。

数据模式按用户配置处理。QQ已接受共享原数据，不把历史隔离失败作为后续QQ任务阻塞；其他应用不自动继承该授权。工具不擅自终止用户进程。

当前不建设：Web工作台、内置编辑器、文件管理器、完整工作区系统、独立模拟预览、管理平台、任意JS撤销及自动导航重注入。完整导出/分发流程不作为最小dev反馈链路前置，其后续范围另行确定。

## 后续验收原则

同类目标只增加配置和验证证据，不新增品牌实现；编辑增量后免重打包并在真实目标确认效果；必要重载/重启和失败可见；每次执行对应文件、版本与目标。已有单应用原型和接口测试不能替代通用性验收。
