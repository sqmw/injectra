# 产品定位与注入边界

## 来源与优先级

2026-11-02用户批注及两张定位图片确立了早期runtime阶段边界：Injectra是代码注入工具／核心，当时只做runtime；使用者负责注入后的应用界面适配，不要求任意JS撤销；管理平台和Agent后置。早期决策见[D-003](DECISIONS.md#d-003)；当前注入时机与dev范围由下文2026-11-12澄清及[D-012](DECISIONS.md#d-012)补充。

2026-10-31已读取[分享对话：Electron脚本注入工具](https://chatgpt.com/share/6ae5d51b-6158-83e8-9f82-5abfcb5f067a)。其中Windows优先、AI编辑器、插件市场、Native Hook及管理规划属于原回答的建议，不自动成为需求。早期来源核对过程见[初始化证据](archive/T-001.md#t-001)；用户后续明确的产品边界优先。

## 定位与注入时机

2026-11-12用户进一步澄清：查看平台是pre-runtime的dev加载模式——先注入少量dev代码，使用现有编辑器修改增量，在真实App直接看更新，避免反复打包。工作台、内置编辑器和完整工作区不在当前目标；[T-040已升级v3](TODO.md#t-040)，依据[D-012](DECISIONS.md#d-012)。当前定义见[dev模式](architecture/dev-mode.md)，旧方案与证据保留；用户随后批准CLI收敛与平台代码删减。

面向以JS、HTML、CSS渲染界面的桌面应用，提供代码注入能力：运行期直接连接执行；pre-runtime可在派生副本中准备引导入口，用户增量保持外置，长期覆盖Electron之外的Web宿主。Web界面是目标类别，不意味着任何应用都已可接入或已验证兼容。

| 方向 | 当前边界 |
| --- | --- |
| runtime注入 | 当前交付：连接已运行且可接入的目标Web运行环境，选择正确页面，执行用户提供的代码并返回结果 |
| pre-runtime / dev模式 | CLI prepare/dev已实现；一次准备后在线更新页面增量。当前支持条件及夹具/Claude/QQ结果见[验收](validation/cli-dev.md) |
| 工作台、内置编辑器、完整工作区、管理平台、Agent | 不在当前范围，也不是dev模式前置 |

runtime / pre-runtime描述注入时机；CDP、Hook等描述接入机制。当前保留CDP，T-017新增Gadget接入并推进WebKit；统一验证接入、正确页面注入及失败判定，不扩张管理功能。

2026-11-11用户将阿里云盘pre-runtime纳入探索与验证候选，由[T-034](TODO.md#t-034)推进。这是新增探索范围，不等于已交付pre-runtime产品后端；入口与所需条件见[核查记录](compatibility/adrive-preruntime.md)。

同日用户明确授权[T-035测试副本资源补丁](TODO.md#t-035)。该路线修改独立副本的Web资源并重新签名，已验证真实登录壳页面执行；[条件与证据](compatibility/adrive-resource-patch.md)单列，不改变当前正式runtime交付，也不把修改后副本的结果外推原安装包兼容。

macOS硬件范围：2026-11-11用户明确仅考虑Apple Silicon，Intel Mac不纳入后续支持或验证计划，见[D-011](DECISIONS.md#d-011)。历史“Intel未验证”保留为当时的证据边界，不继续列作待补项。硬件范围不等于目标进程架构：本次不据此扩张或变更Rosetta/x86_64目标的既有支持声明。

## 插件存放边界

2026-11-05用户明确要求插件统一由独立web-ui-plugins库持有；Injectra不得保存任何实际插件、示例插件或可交付Bundle。已迁移原examples/accent及参考实现中的受控面板；注入runtime、协议/原生桥接仍属于注入器，验证仅生成临时测试输入。插件目录通过用户显式提供的manifest引用，不进入核心构建依赖。迁移证据见[T-016](TODO.md#t-016)。

## 责任边界

| 责任方 | 负责内容 |
| --- | --- |
| Injectra | 平台、宿主与协议层面的接入适配；目标身份与选择；载荷加载及执行；成功、失败或结果未知的可见反馈 |
| 使用者／载荷作者 | JS/HTML/CSS内容；目标控件定位与选择器；应用版本差异；重渲染覆盖；业务交互、页面变化后的再次注入及脚本副作用处理 |

不为每个应用维护主题、控件或业务逻辑适配。真实应用与日常定制示例用于证明注入通道及实际效果，不因此形成长期维护该应用界面的承诺。

注入适配优先按协议、平台/宿主及实际ABI差异复用；应用专有接入例外隔离在适配层。2026-11-11用户确定适配方案的插件化阈值为32：新增第33个正式独立适配方案前完成插件化，不以应用数量计数。计数口径、当前静态装配与插件化验收见[架构边界](architecture/boundaries.md)及[D-010](DECISIONS.md#d-010)。此处的适配扩展与上文独立库中的主题/功能载荷是不同职责。

长期架构按[D-004](DECISIONS.md#d-004)现在建立执行域边界，见[执行域契约](architecture/boundaries.md)。原生目标、地址与独立内存端口已定义；原生测试仅操作自有缓冲区，不代表已支持真实进程注入/修改。

## 当前交付与已有实现

- Rust CLI在macOS提供默认CDP及可选Electron Gadget/WKWebView页面后端；通过显式端口或会话，以精确ID选择主页面。
- 从本地版本化manifest加载CSS/HTML/JS，经单一共享Web runtime执行；平台与宿主接入分别隔离。
- 不可连接、不支持、找不到目标、脚本异常均明确报告；超时或断线保留结果未知语义，不伪报成功或自动重放。
- 标准macOS Electron .app保留只读启动参数规划；Gadget另有显式受控新实例启动脚本，拒绝已有同路径实例，不修改应用包或自动重启用户进程。
- 既有同ID更新、remove、context.onCleanup保留并如实记录；它们是已实现的受管理内容辅助行为，不等于任意JS撤销，也不构成新增回滚系统的要求。本轮删减平台模块，既有辅助接口与历史验收保留。

Rust用于无Node运行时的单可执行文件交付，并为后续原生接入留出实现空间；Node/Electron仅供开发验证。实际命令与辅助接口见[开发说明](dev.md)。

## 当前不承担的能力

自动导航重注入、跨窗口自动恢复、DOM守护、应用控件适配、任意JS撤销、一键回滚、权限管理平台、AI生成与Agent编排仍不属当前交付。当前交付通用准备与轻量CLI dev通道；工作台、内置编辑器和完整工作区已被用户撤出范围。已有局部代码不等于dev通用交付，来源区分只保留必要的文件、版本与执行反馈。

运行页面结束或重建后，原页面内注入状态不延续；使用者需要时重新注入。脚本主动产生的持久化或外部副作用仍由载荷作者负责，工具不承担撤销。

## 验收与证据边界

当前验收聚焦三个问题：能否接入目标运行时、能否把JS/HTML/CSS送入正确页面并实际生效、能否明确失败原因或结果未知。真实应用日常场景可以作为验收载体；长期保持定制效果、导航后恢复或全部应用适配不作为通过条件。

已有受控Electron fixture及豆包定制Chromium页面的实际注入证据，详见[验证记录](validation.md)和[豆包报告](compatibility/doubao.md)。这些证据只覆盖记录中的版本与场景，不证明WebKit、所有Electron应用或任意载荷兼容。协议执行成功与示例的可观察效果分别验证，不把任意用户脚本的业务正确性交给注入工具保证。
