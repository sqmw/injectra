# 需求证据与 MVP 边界

## 已确认

来源：2026-10-31 用户在当前开发对话中的直接要求。

1. 在现有空项目目录初始化 Injectra。
2. MVP 首先支持 macOS 的 Electron 系列应用。
3. 长期存在多个平台、多种宿主体系，注入的 Web 代码应共用。
4. 严格遵守 AGENTS/docs 的模块边界、低耦合、高内聚和可插拔约束，按实际变化点采用设计模式。

## 尚未获得的输入

[用户提供的分享对话](https://chatgpt.com/share/6ae5d51b-6158-83e8-9f82-5abfcb5f067a) 是需求来源，当前未取得正文。
2026-10-31 网页读取超时；浏览器访问显示 `Could not load this ChatGPT conversation`。不能据此判断链接已删除、权限不足或服务故障。

| 缺失内容 | 影响的判断 |
| --- | --- |
| 注入后实现的具体功能与用户流程 | Web 代码职责、产品交互、验收输出 |
| 首批目标应用、版本、可控制程度 | 兼容范围、最小真实验证对象 |
| 分享中已确定的语言、运行形态和方案 | 工程清单、依赖、注入路径、部署方式 |
| 是否允许持久修改目标应用，如何恢复 | 副作用范围、备份与撤销合同 |

这些信息到位前可完成仓库与文档初始化；不得假定目标应用支持调试入口、允许改包，或把某一种注入手段当成既定路线。

## 后续 MVP 验收所需证据（待需求收敛）

- 共享 Web 代码保持单一来源，宿主差异落在适配边界；替身测试与真实应用实测分别报告。
